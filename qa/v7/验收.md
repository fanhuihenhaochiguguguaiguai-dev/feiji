# 苍穹锋刃 V7.0 与 V7.1

## 视觉依据

战斗以参考图 11 的右上空战分区为基准。该图与用户最后确认的画面相同。耐久、速度和高度靠左，雷达在右上，准星和目标留在中央。武器操作保留右下拇指可达区，地面依据武器实际可用性显示按钮。预备页使用参考图 10。第 05 张保存于参考目录，正式战斗采用用户指定的布局。参考图中的虚拟摇杆、联机比分和 VIP 栏已省去。

大厅、机库、机务页、任务、活动、赛季和研发用独立页面呈现。导航图标、翼徽、香槟金指挥框、战术仪表框、冷银机务框和赛季插画提取自用户参考图。金属边框用九宫格切片伸缩，可在不同单位尺寸下保持切角比例。文件 `public/ui-v7/sources.json` 记录全部裁切来源。透视画面、飞机转动、天气、文字、雷达及各项进度由游戏实时绘制。

奖励、升级、出击和选机沿用已有统一配置及存档逻辑。增加基于实际结算的每日任务，奖励按本地日期持久化，发放和领取记录一起提交。赛季奖励使用累计实际经验。机库模型保留 Blender 源文件和三档 GLB。设备安装继续读取兼容性与存档状态。升级预览和实战共用计算公式。

## 缺陷与修复

- 旧版目标画框同时存在两个问题。相机矩阵在 3D 绘制前才刷新，目标投影却提前运行。投影函数还把同一个临时向量作为坐标输入和输出，透视除法因此读到了已经变换的坐标。新版分离两个向量，读取同一渲染帧的相机与机身锚点，按实际画布的 CSS 坐标进行投影。仍在画布内的标记保持原位，越界后改用专门的方向提示。
- 旧版敌机使用固定距离切换细节。新版结合真实屏幕占用和滞回距离选择近、中、远网格。常见敌机预加载，近距离使用 Exterior。屏幕过远时实体会按正常透视缩小，雷达保持真实航迹。
- 旧版大幅拉杆可能在初始一秒内接近垂直，形成明显能量损失。新版将低幅修剪与主动俯仰分开，调整不同滑动幅度的响应，辅助开启时限制陡升角速度和过冲。关闭辅助仍支持连续翻滚等机动。下方表格对应相同 F-16C、起始高度、速度和 90 Hz 固定步长。
- 地形由二档细化为三档，边界法线读取同一高程网格，地表色带考虑坡面、侵蚀、岩层和雪线。海面分离低频波和高频扰动，用视角与像素覆盖控制细纹。云层使用密度积分、受光近似与高空薄云，反射和海面明暗引用相同天空参数。

## 验收限制

参考对照展示每个分区的差异。概念图中的构图、游戏数值、拍摄时间和实际场景会有差异。对照结果供复查视觉差距。场景仍基于现有可编辑模型和地形，机身表面叙事、云的光照层数和背景设备密度距离概念图仍有差距。安卓实体设备、90 Hz 屏幕、持续触控手感和 60/90 FPS 目标需要设备测试。

## 自动化结果

- 12 个逻辑测试通过，包含三波实际交战、耐久和机型差异、反制、海面碰撞、装备奖励闭环、存档恢复、物理爬升、多期任务及雷达坐标。
- Chromium 的 WebGL2 与 WebGPU 均通过出击、锁定、导弹发射、座舱切换及战术雷达。两种后端各取 12 个目标样本，对照 3D 投影与 DOM 边框中心，覆盖 800 × 360、1280 × 720、1536 × 691，目标深度约 179–3,176 米，覆盖三档模型。两种后端的最大误差均小于 0.02 CSS 像素。
- 800 × 360 双触点模拟中，以 79 CSS 像素的手势抬头，同时按住航炮。机头前向向量垂直分量由 0 到 0.313，航炮由 510 减至 498。松手后按住状态清除。
- 界面逐页进入并返回，检查了 14 个独立页面。另捕获 393 × 852 竖屏以及两种宽屏比例的大厅状态。
- 云端使用 Chromium 软件图形后端。800 × 360 实战示例中，该轮分段采样为 WebGL2 战斗约 1.66 FPS、座舱约 2.32 FPS，WebGPU 并行采样约 0.66 和 0.21 FPS。示例存在软件渲染和并行任务竞争，数值仅用于记录环境与复查瓶颈。GPU/CPU 时间、三角面、绘制调用、显存及 1% Low 原始数据随附。
- 浏览器使用实际导弹击落训练敌机，进入胜利结算并发放实际奖励。首次每日奖励增加 150 信用点，保存后被标记为已领取，按钮禁用。前往 `实机画面/result.webp` 和 `实机画面/daily-claim.webp` 查看证据。
- 六个低空与高空场景在两版本以相同战机、位置、航向、天气和视口捕获。新版跟随相机使用调整后的姿态逻辑，画面差异包含相机改动。原图与独立页面的对照裁切区域、叠加和像素差记录于 `对照/`。
- QA 浏览器均未记录资源 404、JavaScript 异常或渲染控制台错误。持续多局负载、实体安卓设备在不同图形硬件上的帧时间及长时间触控仍待验证。
